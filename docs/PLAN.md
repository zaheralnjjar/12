# خطة بناء تطبيق «Nuevo Musulmán»

تطبيق لتسجيل المهتدين الجدد ومتابعتهم، مبني على بنية **تطبيق مناشط الدعاة** (`duat-app`) ومخطط شاشاته وقاعدة بياناته، ويبقى التعامل فيه مباشرةً مع جداول Google ونماذج Google.

- **المرحلة الأولى (أساسية):** ينفّذها Claude في هذا المستودع.
- **المرحلة الثانية (ثانوية مكلفة):** ينفّذها وكيل خارجي، ويراجع Claude كل تسليم قبل دمجه.

---

## أولًا: القرارات المعتمدة في الحوار

| البند | القرار |
|---|---|
| المعمار | نفس `duat-app`: خادم Google Apps Script، وقاعدة بيانات في جدول Google، وواجهة React/TypeScript/Vite، ومصادقة بحساب Google |
| لغة التطبيق | الإسبانية بالكامل: الواجهة ورسائل الخادم والأخطاء |
| المشرف (Supervisor) | يرى كل شيء، ويدير الحسابات والإعدادات |
| المعلم (Maestro) | هو نفسه الشيخ الذي حضر إعلان الإسلام. يرى المهتدين المسندين إليه فقط، ويكتب عنهم الملاحظات والمتابعة |
| المتعاون (Colaborador) | موظف يسجّل مهتدين جددًا فقط، ولا يرى شيئًا بعد الإرسال: لا قوائم ولا بحث ولا تنزيل |
| الراغب في الإسلام | يملأ نموذج Google فقط، ولا يدخل التطبيق |
| المعلمون والجنسيات | قوائم تُدار من الإعدادات، و**تُعطَّل ولا تُحذف** حفاظًا على السجلات القديمة |
| أرقام WhatsApp | أرجنتينية وأجنبية، وتُطبَّع إلى صيغة دولية |
| وثائق الهوية | صور DNI والجواز تُحفظ في Drive، ويراها المشرف والمعلم المسند فقط |
| المخرجات | الشهادة، وملف الشخص، والقائمة الكاملة، والبحث والتواصل |
| ورقة ردود النموذج | تُقرأ قراءة فقط ولا يكتب فيها التطبيق أبدًا، على نمط `63_FormSync.js` |

## ثانيًا: قاعدة البيانات

أسماء الأعمدة بالإسبانية على نمط `SCHEMA` في `server/00_Config.js`. **الإضافة إلى الأعمدة في آخرها فقط**، ولا يُعاد ترتيبها بعد النشر.

| الجدول | الأعمدة |
|---|---|
| `Users` | email, role, maestroId, active, expiry, lastLogin, createdAt |
| `Maestros` | id, nombre, telefono, email, firmaFileId, fotoFileId, active, createdAt, updatedAt |
| `Conversos` | id, nombres, apellidos, nombreIslamico, sexo, fechaNacimiento, nacionalidad, tipoDocumento, numeroDocumento, codigoPais, whatsapp, email, provincia, ciudad, trabajo, estudios, fechaShahada, lugarShahada, maestroId, testigos, diasDisponibles, resumenVida, estado, consentimientoContacto, fechaConsentimiento, origen, formKey, registradoPor, revisar, createdAt, updatedAt |
| `Seguimiento` | id, conversoId, autor, fecha, tipo, resumen, proximaAccion, proximaFecha, createdAt |
| `Progreso` | id, conversoId, etapa, fecha, autor |
| `Documentos` | id, conversoId, tipo, fileId, fileName, mime, uploadedAt, uploadedBy, removedAt |
| `Certificados` | id, numero, conversoId, maestroId, fecha, idioma, fileId, emitidoPor, anulado, anuladoMotivo, createdAt |
| `Settings` | key, value. فيه قوائم الجنسيات ومراحل التتبع ورموز البلدان |
| `Contactos` | يُنقل كما هو من `duat-app`، منفصلًا عن ملفات المهتدين |
| `FormInbox` | يُنقل كما هو، وهو سجل مزامنة النموذج ومنع التكرار |
| `Auditoria` | id, email, accion, objeto, detalle, createdAt. يسجّل تصدير القائمة وإصدار الشهادة وفتح صور الهوية |

**قيم ثابتة:**
- `estado`: activo، sin_contacto، se_mudo، archivado.
- `tipo` في جدول المتابعة: llamada، whatsapp، visita، clase، mezquita.
- `tipo` في جدول الوثائق: dni_frente، dni_dorso، pasaporte، foto، otro.
- `origen`: formulario، colaborador، manual.

## ثالثًا: المرحلة الأولى (ينفّذها Claude)

الهدف: تطبيق يعمل يوميًا بأمان، بالأدوار الثلاثة، وسجل المهتدي، والمتابعة، والمزامنة، والتواصل.

| # | المهمة | معيار القبول |
|---|---|---|
| 1.1 | **تهيئة المستودع:** نسخ `duat-app` أساسًا، وحذف ما يخص تقارير الوزارة (التقارير الشهرية والفصلية وقوالبها، والتجميع، والنماذج الشهرية)، وتغيير اسم المشروع | تمر أوامر `npm run build` و`npm test` و`npm run lint`. ويمنع `.gitignore` رفع أي ملف `xlsx` أو `csv` أو بيانات حقيقية |
| 1.2 | **المخطط:** `SCHEMA` الجديد، و`ensureSheets_()`، وأنواع TypeScript المطابقة | ينشئ الإعداد الجداول كلها في جدول فارغ |
| 1.3 | **البوابة** (`20_Gate.js`): ثلاثة أدوار، و`can_()` على المهتدي، ودعوة المتعاون المحدودة المدة | اختبار رفض لكل دور ولكل إجراء، ومنها: معلم يطلب مهتديًا غير مسند إليه، ومتعاون يطلب قراءة سجل، ومعرّف مخمَّن |
| 1.4 | **الإعدادات:** إضافة المعلمين وتعطيلهم مع إلزام إعادة الإسناد، وإدارة الجنسيات ومراحل التتبع والمستخدمين | لا زر حذف للمعلم. ويبقى اسم المعلم المعطَّل ظاهرًا في السجلات القديمة |
| 1.5 | **سجل المهتدي:** إنشاء وعرض وتعديل وأرشفة، وبحث وتصفية بالاسم والوثيقة والمعلم والحالة والجنسية، وإسناد | لا يعيد الخادم للمعلم إلا مهتديه |
| 1.6 | **مسار المتعاون:** شاشة تسجيل واحدة مع رفع صور الوثائق، ورسالة «تم التسجيل» فقط | بعد الإرسال لا تعيد الواجهة ولا الخادم أي بيانات عن السجل |
| 1.7 | **مزامنة نموذج Google:** قراءة ورقة الردود، وتطبيع الهاتف ورقم DNI والتواريخ، ومنع التكرار بمفتاح `formKey` مع تنبيه عند تطابق DNI أو الهاتف، ووضع علامة `revisar` على ما لا يُفهم، كالتاريخ الملتبس أو اسم شيخ غير معروف | إعادة المزامنة لا تكرّر أي سجل. وتُختبر على بيانات اصطناعية تحاكي الأنماط المرصودة |
| 1.8 | **المتابعة والتتبع:** جدولا `Seguimiento` و`Progreso` على صفحة المهتدي | يكتب المعلم المسند فقط، ويرى المشرف الكل |
| 1.9 | **WhatsApp:** تطبيع الرقم بصيغة 549 للأرجنتين أو المفتاح الدولي، ورابط `wa.me` مع معاينة النص قبل الفتح | اختبارات للرقم الفارغ والرقم غير الصالح والرقم الأجنبي والحروف الخاصة |
| 1.10 | **الوثائق:** رفع صور الهوية والجواز إلى Drive، على نمط `30_Files.js` | تُرفض الأنواع والأحجام غير المسموحة. ولا يرى الصور إلا المشرف والمعلم المسند |
| 1.11 | **تصدير القائمة الكاملة** إلى Excel بالإسبانية | للمشرف وحده، ويُسجَّل كل تصدير في `Auditoria` |
| 1.12 | **الواجهة بالإسبانية** كلها، مع الإبقاء على بنية الشاشات والشريط السفلي | لا يبقى نص عربي في الواجهة |
| 1.13 | **التحقق والتسليم:** فحص الأنواع والتدقيق والاختبارات والبناء، ثم مراجعة أمنية، ثم دليل نشر بالعربية | تقرير يذكر حرفيًا ما فُحص وما لم يُفحص |

> **حدود Claude:** لا يستطيع النشر على حساب Google الخاص بك. خطوات النشر (`clasp push`، وإعداد `CLIENT_ID`، وربط ورقة الردود) تنفّذها أنت وفق الدليل المرفق.

### بروتوكول الإشراف على الوكيل الخارجي

1. **مهمة واحدة لكل تسليم:** يعمل الوكيل على فرع مستقل، ويفتح PR بمهمة واحدة من الجدول.
2. **ممنوعات بلا إذن مسبق:**
   - تعديل `server/20_Gate.js`.
   - تغيير ترتيب أعمدة `SCHEMA` أو حذف عمود منها.
   - إضافة اعتماديات مدفوعة.
   - إدخال بيانات حقيقية في الاختبارات أو المستودع.
   - النشر.
3. **شروط كل PR:**
   - اختبارات للمسار الجديد، ومنها اختبار رفض لكل دور لا يحق له.
   - مرور الفحوص كلها.
   - وصف بما تغيّر وما لم يُختبر.
4. **مراجعة Claude:** يقرأ الفرق، ويشغّل الاختبارات، ويتحقق من أن الصلاحيات لم تتسع، ثم يكتب ملاحظاته على PR.
5. **الدمج:** يدمج المالك وحده بعد موافقة المراجعة.

## خامسًا: قواعد الخصوصية (ملزمة للمرحلتين)

- ملف الردود الحقيقي **لا يُرفع إلى المستودع ولا إلى أي خدمة خارجية**، والاختبارات ببيانات اصطناعية فقط.
- رقم الهوية والصور وتاريخ إعلان الإسلام بيانات شديدة الحساسية:
  - لا تظهر في القوائم.
  - لا تُصدَّر إلا للمشرف.
  - يُسجَّل فتح صور الهوية في `Auditoria`.
- يُوقَف خيار «عرض ملخص النتائج» في إعدادات نموذج Google.
- لا إرسال آلي ولا رسائل جماعية عبر WhatsApp، والتواصل يدوي برابط `wa.me` فقط.
